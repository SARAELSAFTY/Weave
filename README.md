# Weave

Weave is a data-driven narrative prototype for Unity that uses a visual graph system and AI-powered character reactions. The project is built to be modular: cards, characters, and kingdom resources are all dynamic assets that can be changed or expanded without touching the core code.

## Modular Data Architecture

Everything in Weave is treated as a placeholder or a data-driven definition:
- **Cards**: Authored in the visual graph, containing text, choices, and outcomes.
- **Speakers**: Defined as CouncilMemberData assets. You can add new characters by creating new assets and assigning them a unique ID.
- **Resources**: Defined as ResourceData assets. The system does not have hardcoded stats like "Gold" or "Loyalty" — it simply reads whatever is in your ResourceCatalog.

## Kingdom Resource Management

The resource system is fully extensible and non-hardcoded:
- **Adding Resources**: Create a new ResourceData asset, give it an ID/Icon, and add it to the ResourceCatalog. The UI will automatically create a row for it at runtime.
- **Modifying State**: Use the ResourceState component to track values.
- **Card Outcomes**: CardData allows you to define ResourceChange values for each choice, which are applied automatically when the player swipes.

## AI Reaction Mechanics

The most important part of the narrative is how characters react to your choices using the Groq LLM API. The system builds a dynamic prompt for every reaction based on four pillars:

1. **[Persona]**: Taken from the Llm Persona Prompt field on the character's CouncilMemberData asset. This tells the AI how to speak (e.g., "be suspicious," "speak in short sentences").
2. **[Situation]**: Taken from the Llm Prompt Seed on the specific CardData. This gives the AI context for the current story moment.
3. **[State]**: A snapshot of the current game variables, including the Day count and all current Resource values.
4. **[History]**: Provided by the PlayerHistoryTracker, which gives the AI context on the last 3 decisions the player made.

## Configuration & Options

### LLM Settings
You can fine-tune the AI behavior in the LlmSettings asset:
- **Groq Model**: Choose which LLM model to use (default: llama-3.3-70b-versatile).
- **Temperature**: Adjust randomness (0 = predictable, 2 = creative).
- **Max Tokens**: Limit the length of AI responses (default: 150).
- **Timeout**: Set how long to wait for the API before auto-advancing the game.

### Card Options
In the Inspector for any CardData asset:
- **Is Llm Reaction Card**: Toggle this to make the card text generated by AI instead of using the authored description.
- **Llm Prompt Seed**: The specific instructions for the AI for this card.
- **Continue Next Card ID**: Where the game goes after the AI reaction is shown.

### Speaker Options
In the CouncilMemberData asset:
- **Is Llm Speaker**: Enables AI reactions for this character.
- **Llm Persona Prompt**: The core "personality" instructions for the AI.

## Editor Workflow: Card Graph

The **Card Graph** (Weave > Card Graph) is the central hub for building your game:
- **Visual Branching**: Connect cards to define the flow of the story.
- **Resource Integration**: Drag resources into the graph to see how they connect to choices.
- **Auto-Sync**: The NarrativeAssetPostprocessor automatically keeps your asset IDs in sync with their file names, so you don't have to worry about broken references when renaming files.

## Setup & Running

1. **API Key**: Create a file at Assets/Game/Resources/groq_api_key.txt and paste your Groq API key inside.
2. **Open Scene**: Load Assets/Game/Scenes/Game.unity.
3. **Check References**: Ensure the GameManager in the scene has a NarrativeDatabase, ResourceState, and LlmSettings assigned.
4. **Play**: Use **A/D** or **Left/Right Arrows** to make choices.

## Common Development Tasks
- **Add a Resource**: Create a ResourceData asset -> Add to ResourceCatalog.
- **Add a Speaker**: Create a CouncilMemberData asset -> Assign ID -> Check Is Llm Speaker.
- **Create a Story Loop**: Use the **Card Graph** to create new nodes and link them via leftNextCardId or ightNextCardId.

# Weave

**Weave** is a bilingual (**English / Arabic**) narrative card strategy game built in Unity 6 with URP.
Inspired by royal swipe-decision mechanics (*Reigns*), it marries tightly structured narrative
decision trees with real-time generative AI dialogue: characters answer your rulings, argue petitions
across several turns, and chat with you freely — while the kingdom's **Crown**, **Gold** and
**Army** answer for everything you decide.

Every AI feature is backed by authored static fallbacks, so the game is **100% playable offline**
with no network connection and no API key. An internet connection is recommended, though, and the
game is at its best with your own free API key.

Play the web build on [itch.io](https://debo0.itch.io/weave).

## How it plays

Reach a verdict on each card by dragging or swiping it, or with the keyboard.

| Input | Action |
| --- | --- |
| Drag / swipe the card | Choose left / right |
| `A` / `←` — `D` / `→` | Choose left / right |
| Swipe down / `S` / `↓` | Middle option on the three-way verdict |
| `Esc` | Pause (the AI button inside reopens the AI settings panel) |
| Language toggle in menus (`F10` in the Editor) | English ↔ Arabic |

Cards come in five shapes:

- **Choice** — a straight decision with two authored outcomes.
- **Reaction** — you decide, then the character answers you in generated dialogue.
- **Petition** — an audience member argues their case across several turns; you can type a reply,
  and the verdict moves resources.
- **Chat** — a free-form conversation with a character. Talk only: no JSON contract, no resource
  stakes; the audience button ends it and advances the story.
- **Ending** — the run stops; an epilogue is generated from how you ruled.

Resources sit on a 0–100 scale. Each swipe shows what it costs: **+10 Gold / -5 Army** on the
choice labels. When a resource drops to 30% of its starting value an advisor warns you; if one
hits 0 the kingdom collapses and the run ends. The collapse ending is not a normal card: its
epilogue is generated by the LLM from the story of your run, and it can fall back to an authored
ending card when generation is unavailable.

The shipped story is **The Wicked King**: you are King Perceval, haunted by your dead mother,
needled by your bastard-half-brother jester, and surrounded by a blunt General, a silken
Chancellor, and a Treasurer who adores you the way a tick adores a hound. A run spans roughly
14–22 cards across three acts — the Eastern question, the circus season, and the Western threat —
and ends in one of six authored endings (two brothers, abdication, tyrant, shadow king, warlords'
peace, or merchant king) unless misrule empties a resource first and the realm writes your
epilogue for you. Which ending you get depends on Crown, Gold, Army, and the flags you set —
burning the portrait, welcoming the circus, jailing the Chancellor.
Every run includes a chat, a petition, and a generated reaction, woven into the plot.
The story data is generated from `Tools/build_story.py` (rerunnable; GUIDs are stable), and
`Tools/verify_story.py` re-checks the graph on disk: route lengths, reachability of every card
and ending, and the chat/petition/reaction guarantee on every route.

## Getting started

### Requirements

- Unity `6000.0.79f1` — the exact version the project uses.
- [Git LFS](https://git-lfs.com) — the art and audio files are stored with LFS.
- Everything else, including the Arabic text stack RTLTMPro, installs automatically when the
  project opens for the first time.

### First launch

1. Clone the repo, open it in Unity Hub, and let it compile.
2. Open `Assets/Game/Scenes/Game.unity` and press Play.
3. On first run the AI settings panel appears — pick a connection, or continue without one and
   play on the built-in dialogue. You can change this anytime from the AI button on the start
   screen or in the pause menu.

### Building for the web

Switch to the WebGL platform in **File → Build Settings** and build. The web template
(`WeaveResponsive`) and anti-aliasing are already configured in the project.

## Choosing an AI connection

Characters that speak live need a chat-completions endpoint. Two ways to get one, both reachable
from the in-game panel:

| Pathway | Setup | Privacy & security |
| --- | --- | --- |
| **Shared connection** (default) | Zero-config out of the box. | Requests route through a Cloudflare Worker that holds a dev-owned key. It is rate-limited and shared with every other player, and enforces a 20 KB body cap. |
| **Your own key (BYOK)** | Paste a [Groq key](https://console.groq.com/keys) — the free tier is enough. | The key is validated against Groq's models endpoint (no tokens spent), stored only in `PlayerPrefs` on your device, and your chat requests go **directly to api.groq.com**, never through the shared worker. |

The panel's status line shows whether the shared connection is currently working, and the console
logs the exact reason when it isn't.

Whichever line you pick, generation is never load-bearing: reactions, warnings, petition turns and
epilogues all fall back to authored text when the service is down.

### The fallback system

Generation writes flavor, never gameplay: every piece of text the LLM can produce has an authored
twin, so a missing network or key changes the wording of a moment, not whether the game plays.

- **What has a fallback** — reaction lines, advisor warnings, petition opening and closing turns,
  rate-limit and send-failure notices, petition and chat button labels, speaker lines, and
  collapse-ending epilogues — each resource carries its own collapse text plus an authored
  fallback ending card.
- **What triggers it** — no network, timeouts, rate limits, a missing or rejected key, or a reply
  the parser can't read. The swap is instant: the same turn simply plays with the authored text.
- **Key failover (HTTP 401)** — a stored key rejected mid-session is disabled for that session
  and the same request re-sends through the shared connection, so play never blocks.
- **Output sanitization** — `LlmTextSanitizer` strips reasoning tags (`<think>...</think>`),
  stage directions (`*sighs*`), markdown code fences and non-Arabic glyphs in Arabic mode.

### Running your own shared endpoint

The worker lives in [`proxy/`](proxy/README.md) — deployment and its caveats are documented there.
Point the **Proxy URL** field on the scene's `LlmReactionClient` component at your deployment to
use it instead of the bundled one. The Groq model itself (default `qwen/qwen3.8-27b`) is set on
the `LlmSettings` asset.

## Authoring content

Open the visual graph editor via **Weave → Card Graph**:

- **Node types** — `CardNode` (dialogue, choices, resource deltas), `SpeakerNode` (portraits,
  persona prompts) and `ResourceNode` (limits, icons, thresholds).
- **Live validation badges** — real-time tags highlight `START`, `LLM`, `PETITION`, `COMMONER`,
  `ENDING` or `DEAD END` (unlinked branches).
- **Persistent layouts** — node coordinates serialize into `NarrativeDatabase.asset` and survive
  reloads.

Custom inspectors cover every definition asset, and required fields fail fast in the Console.

## Project structure

```
Weave/
├── Assets/Game/
│   ├── Art/                       # Card art, portraits, fonts
│   ├── Data/                      # All definition assets (see below)
│   │   ├── NarrativeDatabase.asset        # Story graph: cards, speakers, catalog, graph layouts
│   │   ├── LlmSettings.asset              # Endpoint, model, generation knobs
│   │   ├── LlmPromptTemplates.asset       # Persona seeds: reactions, petitions, chat, commoners
│   │   ├── FontSettings.asset             # Per-language font assignments
│   │   ├── ResourceCatalog.asset          # Crown / Gold / Army wiring
│   │   ├── Cards/                         # One asset per story card
│   │   ├── Speakers/                      # One asset per recurring character
│   │   ├── Resources/                     # Resource definitions with thresholds & endings
│   │   └── CardVisual/                    # Card visual template presets (per-part sprites)
│   ├── Scenes/Game.unity          # The only scene
│   └── Scripts/                   # Game.Runtime assembly (Game.Editor for tooling)
│       ├── Definitions/           # ScriptableObjects: CardData, SpeakerData, ResourceData,
│       │                          #   NarrativeDatabase, ResourceCatalog, CardVisualTemplate
│       ├── Narrative/             # NarrativeRunner, ResourceState, warning monitor, history
│       ├── Llm/                   # Groq HTTP client, audience flow controllers (petition/chat),
│       │                          #   sessions, prompt builder, fallback text, sanitizer
│       ├── Localization/          # LanguageManager, RtlTextHelper, LocalizedText, FontSettings
│       ├── UI/                    # Card views, HUD, AI settings panel, menus
│       ├── Input/                 # Touch swipe & keyboard controls
│       ├── Music/                 # MusicController
│       ├── Editor/                # Card Graph window and custom inspectors (editor-only)
│       └── GameManager.cs         # Composition root: orchestration of everything above
├── proxy/                         # Cloudflare Worker reverse proxy (shared connection)
└── WebGLTemplates/WeaveResponsive # Container-filling web build template
```

### Architecture in one page

| Component | Responsibility |
| --- | --- |
| `GameManager` | Orchestration: input, pause, card presentation, audience routing, warnings, endings, restart, AI panel wiring |
| `NarrativeRunner` | Choice resolution, resource changes, day counter, story-graph validation at startup, ending and collapse detection |
| `ResourceState` / `ResourceWarningMonitor` | Resource values, warning thresholds, game-over limits |
| `AudienceFlowController` | Shared skeleton for both audience types: dependencies, speaker lifecycle (defined or runtime-generated commoner), kingdom snapshots, teardown |
| `PetitionFlowController` / `ChatFlowController` | Petition: proposal/exhaustion logic and resource verdicts. Chat: free multi-turn conversation |
| `AudienceSession` subclasses | Conversation history carried across turns so the model always knows what was said |
| `LlmReactionClient` | The single HTTP gateway: direct Groq with BYOK, shared proxy fallback, key validation, health probe |
| `LlmPromptTemplates` / `SpeakerPromptBuilder` | Prompt assembly from persona seeds and kingdom state |
| `TempSpeakerFactory` | Runtime-only commoner speakers, named by the model mid-audience |
| `LlmFallbackText` / `LlmTextSanitizer` | Authored fallbacks and generated-text cleanup |

## Developer guidelines

| Topic | What to know |
| --- | --- |
| Arabic text | Always set text through `RtlTextHelper` or `LocalizedLabel` — writing to `TMP_Text.text` directly breaks Arabic shaping. |
| Font assets | Ignore changes to `*.SDF.asset` files; Unity rewrites them on its own while the editor is open. |
| Missing references | Required scene references report an error at startup instead of failing silently later. |
| Fresh start | **Edit → Clear All PlayerPrefs** wipes a stored BYOK key. |
| Assemblies | Runtime code is `Game.Runtime`; editor tooling is `Game.Editor`, which never ships in builds. |
